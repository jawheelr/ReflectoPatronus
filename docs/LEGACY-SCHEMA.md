# The legacy system database: schema discovery

Source: `Copy.bak`, full backup of the legacy database (restored as `legacydata`), taken on SQL Server 2014 (MSSQL12, instance `QUEST`), 2026-11-18. Restored read-only into a throwaway SQL Server 2022 container for inspection. **This document contains structure only, no customer data.**

## Summary
- 99 tables (about 39 hold data), 12 views, **0 foreign keys, 0 triggers, 0 stored procedures** (some scalar functions exist, e.g. `dbo.InvDocNum`). Relationships are implicit in column names (`*_CustId`, `Lin_InvId`, `Prc_FptId`, `Att_InvId`) and must be inferred and verified during import.
- Every table has an `Id int` primary key. Most have `Create_/Update_ UserID/TimeStamp` audit columns.
- **10GB is almost entirely `GQAttach`** (`Att_Contents varbinary`): about 16k real attachments, mostly JPEG photos (about 9.3GB), plus PDFs (about 200MB). The real business data is under about 400MB. The import must stream attachments, not load them into memory.
- All documents are **flat glass** mode (`Inv_AorF = 'F'`) with `Inv_InvType = 'P'`. The auto-glass columns (`Inv_A_*`, `Lin_A_*`, `Cust_A_*`) are present but unused.
- Document types (`GQINV.Inv_Doc_Type`): `I` invoice 33,633; `Q` quote 6,829; `W` work order 1,556; `C` credit 18; `R` 2. Date range 2003-09 to 2026-11. Customer types (`Cust_Type`): `A` 11,064; `B` 1,276; `D` 1.
- Quotes, work orders and invoices are one table (`GQINV`) distinguished by `Inv_Doc_Type`. Document number = prefix + number + suffix.

## Business logic found in views (must be reproduced)
- `CustomerBalance`: customer balance = `SUM(ar_debit) - SUM(ar_credit)` over `GQAR`, grouped by `ar_cust_id`.
- `Receivables`: per customer and invoice, balance, credits, debits and last payment date, from `GQAR`.
- `InvoiceTotals` / `GQInvView` / `TaxBreakdown`: document totals are derived (not stored) from `GQLIN` split into labor, material subtotal, kit, fabrication, flat-glass and flat-part buckets, plus `GQInvTax`. **The importer must reconcile against these views.**
- Other views: `PartName`, `POLinReceived`, `PartOnHand`, `FlatPartSales`, `StorageOnHand`, `GQARView`, `SundryLookup`.

## Import risks and open questions
1. No FKs, so orphaned rows are likely (lines without headers, payments for deleted customers). The importer needs an orphan report.
2. Totals are computed by views and a scalar function, so the full view and function definitions must be ported before totals can be reconciled.
3. Money fields are `numeric(16,2)`; keep exact decimals (never float).
4. Tax: `GQInvTax` rows hold amounts per code. Confirm whether rounding rules live in app code (not in the DB), and compare computed vs stored totals on a sample.
5. `GQUserLog` (265k) is an audit trail. Decide whether to import it or archive it.
6. Passwords in `GQUSER` must not be copied. New users need fresh credentials.
7. `Inv_WO_Instr` is a `text` column and `Att_Contents` is `varbinary`; check encodings (legacy codepage, SQL_Latin1).
